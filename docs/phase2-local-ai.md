# ทดลอง Phase AI บนเครื่องพัฒนา

เอกสารนี้ใช้ **หุ่นและแผนที่จำลอง** เพื่อทดสอบ Kiosk → Qwen → Backend → งานนำทางก่อนย้ายไป Jetson Xavier NX 8GB ผลความเร็วบนพีซีใช้แทนผล benchmark ของ Jetson ไม่ได้

## สิ่งที่ทำงานแล้ว

- ข้อความภาษาไทย/อังกฤษจาก Kiosk ส่งผ่าน device token ไปยัง Backend แล้วให้ Qwen จำแนก intent ในชุดปิด 6 รายการ
- Backend ตรวจผล JSON, confidence ขั้นต้น, แผนที่ที่เผยแพร่, POI สาธารณะ และงานที่กำลังทำ ก่อนเรียกบริการงานนำทาง
- ทางสั่งงาน AI รุ่นทดลองเปิดเฉพาะ `ROBOT_MODE=sim` เพื่อไม่ให้คำขอไปถึงหุ่นจริงก่อนตรวจรับ
- `navigate_to`, `where_is` และ `cancel_job` ทำงานกับหุ่นจำลอง; คำสั่งหยุดสั้น ๆ เช่น `หยุด` หรือ `stop` และคำถามตำแหน่งที่ตรงกับ POI สาธารณะชัดเจน ข้ามการรอโมเดล
- `answer_question`, `check_in_visitor`, `call_reception` ถูกปฏิเสธและบันทึกไว้จนกว่าจะมีข้อมูลอาคาร/บริการปลายทางจริง
- เก็บบทสนทนาและเหตุผลที่ปฏิเสธใน `ai_conversations` และ `ai_rejections`; ในโหมด PostgreSQL ข้อมูลจะถูกบันทึกหลังคำขอสำเร็จ
- Kiosk แสดงสถานะของระบบตาม `/api/kiosk/ai-status`; **ไมโครโฟนยังปิด** เพราะ STT/TTS ยังไม่เชื่อม
- ทาง `/api/kiosk/chat` สนทนาด้วยข้อความหลายรอบ ตอบแบบทยอยแสดง และเลือกทางตอบทั่วไป ข้อมูลห้อง ค้นเว็บ หรือคำสั่งหุ่น คำสั่งหุ่นยังผ่านตัวตรวจเดิม
- การค้นเว็บใช้ SearXNG ที่รันใน Docker ผ่าน Backend โดยไม่ต้องซื้อคีย์ Search API; เมื่อบริการค้นหาไม่พร้อม ระบบบอกว่าตรวจข้อมูลล่าสุดไม่ได้ แทนการแต่งคำตอบ

คะแนน confidence ที่โมเดลรายงานเป็นค่าประเมินของโมเดล ยังไม่ได้ปรับเทียบจากชุดทดสอบจริง จึงไม่ใช้คะแนนอย่างเดียวในการอนุญาตคำสั่ง

## เปิดชุดจำลองแยกจากระบบเดิม

ต้องมี Node.js, pnpm, `llama-server` จาก [llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), และ token ของ Kiosk ที่ตั้งตรงกับ Backend ตาม `README.md` ตัวอย่างนี้ใช้พอร์ต 8080, 4100, 3002 และ 3003 จึงไม่ทับบริการเดิมที่พอร์ต 4000/3000/3001

1. ดาวน์โหลด [Qwen3.5-2B Q5_K_M GGUF](https://huggingface.co/bartowski/Qwen_Qwen3.5-2B-GGUF/blob/main/Qwen_Qwen3.5-2B-Q5_K_M.gguf) ไปที่ `.models/Qwen_Qwen3.5-2B-Q5_K_M.gguf` (โฟลเดอร์นี้ถูกละเว้นจาก Git) ไฟล์ที่ทดลองมี SHA-256 `3f50d5f830873c22d33558f69eb2c34aa59858f37e7a58a982aae88bb38ebe88`
2. เปิดเทอร์มินัลที่รากโปรเจ็กต์ แล้วรันโมเดล:

   ```powershell
   llama-server -m .models\Qwen_Qwen3.5-2B-Q5_K_M.gguf -c 2048 -t 6 -ngl 99 --reasoning off --host 127.0.0.1 --port 8080 --alias qwen3.5-2b --no-webui --cors-origins http://127.0.0.1:4100
   ```

3. เปิดเทอร์มินัลที่สองเพื่อรัน Backend พร้อมแผนที่และหุ่นจำลอง:

   ```powershell
   $env:DB_MODE='memory'
   $env:ROBOT_MODE='sim'
   $env:AI_MODE='local'
   $env:PORT='4100'
   $env:CORS_ORIGIN='http://localhost:3000,http://localhost:3003'
   pnpm --filter @hermes/backend dev
   ```

4. เปิดเทอร์มินัลที่สามเพื่อรัน Kiosk โดยให้ `apps/kiosk/.env.local` มี `KIOSK_TOKEN` ตรงกับ `.env`:

   ```powershell
   $env:API_URL='http://127.0.0.1:4100'
   $env:KIOSK_DIST_DIR='.next-ai'
   pnpm --filter @hermes/kiosk exec next dev -p 3002
   ```

5. เปิดเทอร์มินัลที่สี่เพื่อดูประวัติคำขอใน Admin:

   ```powershell
   $env:NEXT_PUBLIC_API_URL='http://localhost:4100'
   pnpm --filter @hermes/admin exec next dev -p 3003
   ```

6. เปิด `http://localhost:3002/kiosk` แล้วกด **คุยกับผู้ช่วย AI** เพื่อทดลองถามทั่วไปหรือพิมพ์คำสั่ง เช่น `พาไปห้อง 101`, `หยุด`, `ห้อง 102 อยู่ที่ไหน` ถามต่อในหน้าเดียวกันได้ และกดเริ่มใหม่เพื่อล้างบริบทบนจอ ดูบทสนทนาและคำสั่งที่ถูกปฏิเสธที่ `http://localhost:3003/ai` โดยล็อกอินบัญชีทดลองโหมด memory ตาม `README.md` ตัวอย่างแผนที่นี้เป็นข้อมูลสมมติ ห้ามใช้พิกัดกับหุ่นจริง

### เปิดการค้นอินเทอร์เน็ตด้วย SearXNG

SearXNG เป็นบริการค้นเว็บแบบ self-hosted ตาม [คู่มือติดตั้งด้วย container](https://docs.searxng.org/admin/installation-docker) โปรเจ็กต์นี้ใช้ Docker Compose โปรไฟล์ `ai` และเปิดพอร์ต `127.0.0.1:8888` เท่านั้น เพื่อไม่ชนโมเดลที่พอร์ต 8080 ไฟล์ [settings.yml](../searxng/settings.yml) เปิด [ผลลัพธ์ JSON](https://docs.searxng.org/dev/search_api.html) สำหรับ Backend และปิดตัวจำกัดคำขอเพราะใช้งานเฉพาะเครื่องนี้

1. สร้างค่า `SEARXNG_SECRET` แบบสุ่มใน `.env` ที่รากโปรเจ็กต์ตาม `.env.example` แล้วเปิดบริการค้นหา:

   ```powershell
   docker compose --profile ai up -d searxng
   ```

2. ตรวจว่าบริการตอบ JSON:

   ```powershell
   Invoke-RestMethod 'http://127.0.0.1:8888/search?q=Central+promotion&format=json'
   ```

3. เริ่ม Backend ในโหมด AI ตามขั้นตอนด้านบน โดยค่าเริ่มต้น `SEARXNG_URL=http://127.0.0.1:8888` จากนั้นรีเฟรช Kiosk ควรเห็นสถานะ **ค้นเว็บพร้อม** ถาม “ตอนนี้ Central มีโปรโมชั่นอะไรบ้าง” แล้วตรวจคำตอบและลิงก์แหล่งข้อมูล

SearXNG ไม่ใช่คลังข้อมูลอินเทอร์เน็ตในเครื่อง มันส่งคำค้นไปยัง search engine ภายนอก จึงยังต้องมีการเชื่อมต่ออินเทอร์เน็ต ผลลัพธ์อาจว่างหรือถูกจำกัดเมื่อ search engine ป้องกัน bot การค้นได้ผลลัพธ์ไม่ได้ยืนยันว่าโปรโมชั่นหรือรายละเอียดในหน้าเว็บยังมีผลอยู่ จึงควรตรวจข้อมูลสำคัญกับแหล่งต้นทาง

หากไม่ต้องการเปิด AI ให้ใช้ `AI_MODE=off` ซึ่งเป็นค่าเริ่มต้น คำขอ `/api/kiosk/intent` จะคืน `501` ไม่มีการสร้างงานโดย AI

## ผลทดลองบนเครื่องนี้ (5 ตุลาคม 2569)

เครื่องทดสอบมี Intel Core i5-8400, RAM ประมาณ 20 GB และ AMD Radeon RX 7900 XTX ใช้ `llama-server` รุ่น build 10545 กับโมเดลข้างต้น คำขอ “พาไปห้อง 101” ใช้ประมาณ 11.6 วินาทีในครั้งแรก; “พาไปห้อง 103” ใช้ประมาณ 9.2 วินาที และสร้างงาน `kiosk_voice`; คำว่า “หยุด” หลังจากนั้นใช้ประมาณ 45 มิลลิวินาทีและยกเลิกงานได้ เวลาเหล่านี้เป็นเวลารวมของคำขอในเครื่องทดสอบ ไม่ใช่ TTFT หรือผล Jetson

## งานถัดไป

เป้าหมายถัดไปขยายเป็นแชตบอตทั่วไปที่ถามต่อได้ ไม่จำกัดเฉพาะคำสั่งหุ่นหรือเรื่องโปรโมชั่น ดูข้อกำหนดและลำดับงานที่ปรับแล้วใน [SPEC.md](../SPEC.md) และ [PROGRESS.md](../PROGRESS.md)

1. ทำบทสนทนาด้วยข้อความ บริบทช่วงสั้น และคำตอบแบบทยอยแสดง
2. ให้ Backend เลือกใช้การตอบทั่วไป ฐานข้อมูล อินเทอร์เน็ต หรือเครื่องมือสั่งงานตามคำขอ รวมถึงการถามกลับและคำขอหลายขั้นตอน
3. เพิ่มการค้นเว็บที่แสดงแหล่งข้อมูลและเวลาที่อัปเดต พร้อมแจ้งเมื่อข้อมูลล่าสุดตรวจไม่ได้
4. ทดสอบคำตอบและคำสั่งหุ่นจำลอง แล้ววัด LLM, STT และ TTS บน Jetson ก่อนเปิดเสียงและใช้งานกับหุ่นจริง
