# คำสั่งหุ่นภาษาธรรมชาติและ benchmark

อัปเดต 7 ตุลาคม 2569 — ใช้ Qwen3.5-2B local บนเครื่องพัฒนา; Jetson ยังพักไว้

## วิธีที่ใช้

1. **รูปประโยคและชื่อเรียกอื่น:** จับคำขอไทย/อังกฤษหลายสำนวน เช่น “ช่วยพาไปที่หน้าประตูหน่อย”, “ไปส่งที่หน้าประตูได้ไหมครับ” และ “Could you take me to the entrance?” เพิ่มชื่อเรียกอื่นในหน้า Admin → แผนที่ → เลือก POI → ช่องชื่อเรียกอื่น → บันทึก ชื่อเรียกเก็บใน metadata.aliases บนหุ่นและอ่านกลับตรวจสอบก่อนรายงานสำเร็จ
2. **ตีความด้วยโมเดล:** ประโยคที่กฎยังจับไม่ได้ส่งให้โมเดลคืน JSON ที่มี intent, confidence, poiCode, speechAct และ needsClarification ตัวอย่าง “หน้าประตูคือจุดหมายของผม คุณช่วยไปส่งผมที่นั่นได้ไหม” Backend ตรวจ schema และอนุญาตเฉพาะรหัส POI จากรายการจริง ตรวจชื่อที่ระบุและอ่านพิกัดใหม่ก่อนสร้างงาน

เว็บผู้ช่วยอยู่ http://localhost:3001/ai เมื่อกดส่งคำขอที่ชัดเจนจะสร้างงานตามสิทธิ์และสถานะหุ่น ส่วน benchmark ด้านล่างเป็น dry-run ทั้งหมด

ชื่อซ้ำ หลายจุดหมาย ไม่พบชื่อ หรือ “ห้องนั้น” ที่ไม่มีบริบท จะถามให้ระบุใหม่ ยังไม่เก็บคำตอบถามกลับเป็นคำสั่งค้างและยังไม่มีการนำทางหลายขั้นตอน คำปฏิเสธ สมมติ และข้อความที่ยกมาไม่ส่งคำสั่งเดิน ส่วนคำหยุดที่รองรับไม่ต้องรอโมเดล

## รันทดสอบ

เปิด local AI ก่อน แล้วรันจากโฟลเดอร์โปรเจ็กต์:

```powershell
pnpm --filter @hermes/backend benchmark:ai -- --label hybrid
pnpm --filter @hermes/backend benchmark:ai -- --strategy model --label model
pnpm --filter @hermes/backend benchmark:ai -- --strategy legacy --label legacy-repeat
pnpm --filter @hermes/backend benchmark:ai -- --repeat 3 --label hybrid-repeat
pnpm --filter @hermes/backend benchmark:ai -- --case semantic-tail --label one-case
```

`hybrid` คือระบบที่ใช้งานจริง: ใช้กฎก่อนและโมเดลเมื่อจำเป็น `model` ใช้โมเดลเป็นหลัก แต่ยังใช้กฎหยุดและกันคำปฏิเสธ/สมมติ/ข้อความยกมา `legacy` คือ policy เดิมที่เก็บไว้เฉพาะเพื่อเปรียบเทียบ ไม่ใช้สั่งหุ่นจริง

ชุดข้อมูล [cases.json](../benchmarks/robot-ai/cases.json) มี 40 กรณีและ 6 POI จำลอง ครอบคลุมคำขอสุภาพ ชื่อเรียกอื่น ประโยคอ้อม กลับแท่น หยุด คำถาม สถานะ คำปฏิเสธ ชื่อกำกวม จุดส่วนตัว และการแทรกคำสั่ง ผลเขียนเป็น JSON และ Markdown ใน reports/ai-benchmark ตาม label คำสั่งคืน exit code 1 เมื่อมีกรณีไม่ผ่าน ข้อผิดพลาด หรือเสนอเดินผิดเจตนา/ผิดจุดหมาย

Runner บังคับฐานข้อมูลในหน่วยความจำ หุ่นจำลอง dryRun=true และ network allowlist เฉพาะ origin ของโมเดล ตรวจว่าไม่มี job ถูกสร้าง จึงไม่เรียก API ของหุ่นจริง

## ผลบนเครื่องพัฒนา

| ระบบ | ผ่าน | เสนอเดินผิดเจตนา/จุดหมาย | Median | p95 |
|---|---:|---:|---:|---:|
| ก่อนปรับปรุง | 21/40 (52.5%) | 4 | 2,986 ms | 6,120 ms |
| กฎ + โมเดล | 40/40 (100%) | 0 | <1 ms | 4,684 ms |
| โมเดลเป็นหลัก + กฎความปลอดภัย | 40/40 (100%) | 0 | 4,487 ms | 7,264 ms |

ดูรายละเอียดรายกรณีใน [baseline.md](../reports/ai-benchmark/baseline.md), [hybrid.md](../reports/ai-benchmark/hybrid.md) และ [model.md](../reports/ai-benchmark/model.md)

ผลนี้เป็นชุด regression ที่ใช้พัฒนา ยังไม่ใช่ชุดทดสอบภาษาใหม่ที่โมเดล/ผู้พัฒนาไม่เคยเห็น และไม่รับประกันความถูกต้องของทุกประโยค คะแนนคำนวณจากผลรวมการจำแนกและ policy ของ Backend ค่า latency เป็นเวลารวมต่อคำสั่ง ปัดเป็นมิลลิวินาที; 0 ms หมายถึงต่ำกว่า 0.5 ms ไม่ใช่ไม่มีเวลาประมวลผล มีการใช้ prompt cache ได้ และไม่ได้วัด TTFT, RAM สูงสุด, STT/TTS, การเดินจริง หรือ Jetson รอบ model มีการตรวจ Kiosk ร่วมช่วงต้น จึงอาจมีการรอคิวและไม่ควรใช้เทียบประสิทธิภาพอย่างเคร่งครัด หลีกเลี่ยงเปิดคำขอ AI อื่นระหว่างรันเพื่อเทียบเวลาอย่างเหมาะสม
