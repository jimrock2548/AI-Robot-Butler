# Mock Test — จำลองว่าเชื่อมต่อ Hermes

โหมดนี้แสดง UI เส้นทางเดียวกับแผนที่สดของหุ่น มี telemetry, SLAM grid, LiDAR จำลอง 360 จุด, แท่นชาร์จ และ POI 4 จุด: หน้าประตู จุดต้อนรับ ห้องประชุม และห้องครัว หน้าจอมีป้าย MOCK TEST และ API คืน simulated=true, mockConnected=true

เริ่ม Backend จากรากโปรเจ็กต์:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-robot-mock.ps1 -LocalAI
```

เปิดเว็บ Admin/Kiosk ตามปกติที่พอร์ต 3000/3001 หากใช้พอร์ต 4000 อยู่แล้ว ให้หยุด Backend ตัวเดิมก่อน แล้วรีเฟรชเว็บ เข้าระบบทดลองด้วย admin/admin123 (หรือ operator/operator123, viewer/viewer123) เซสชันจากฐานข้อมูลจริงจะต้องเข้าสู่ระบบใหม่

Mock แยกข้อมูลไว้ในหน่วยความจำ แม้ตั้ง DB_MODE=pg ไว้ก่อนก็ไม่อ่าน/เขียนฐานข้อมูลจริง ไม่เปลี่ยน .env, token หรือรหัสผ่านจริง เมื่อปิด Backend งานและ POI ที่แก้ในโหมดนี้จะหาย เมื่อกลับไปใช้ start-robot-control.ps1 จะใช้ฐานข้อมูล/หุ่นจริงตามค่าของสคริปต์เดิม ไม่มีการสลับกลับอัตโนมัติ

MockHermesClient ใช้ fixture และ RobotSim แทนคำขอเครือข่าย มี fetcher สำรองที่ throw หากเส้นทางใดพยายามเรียก API หุ่น รองรับดูสถานะ แผนที่ POI CRUD ควบคุมด้วยมือ นำทาง ยกเลิก กลับแท่น และ E-Stop/reset แบบจำลอง ปิด auto dock ไว้ คำสั่ง AI ยังใช้โมเดล local จริงหากเปิดพร้อมกัน

การเคลื่อนที่เป็นภาพจำลอง ไม่ได้จำลอง SLAM การหลบสิ่งกีดขวาง การวางแผนเส้นทาง หรือฟิสิกส์ของ Hermes อย่างครบถ้วน จึงใช้ตรวจหน้าตาและการไหลของงาน ไม่ใช้แทนผลตรวจรับฮาร์ดแวร์

ตรวจระบบที่เปิดอยู่ด้วย node scripts/check-robot-mock.mjs สคริปต์จะยืนยัน mockConnected ก่อนส่งคำสั่งใด ตรวจแผนที่/Kiosk/AI dry-run และขยับเฉพาะหุ่นจำลอง จากนั้นยกเลิกเฉพาะงานทดสอบที่สร้างเอง หากมีงานหรือ lock อยู่จะไม่ทำการทดสอบคำสั่ง
