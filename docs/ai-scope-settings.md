# เลือกขอบเขตการทำงานของ AI

ผู้ดูแลระบบเปิดหน้า **AI → ขอบเขตการทำงานของ AI** (`http://localhost:3000/ai`) แล้วเปลี่ยนสวิตช์ **จำกัด AI เฉพาะบริการนำทาง**

| สวิตช์ | การทำงาน |
|---|---|
| เปิด | รับงานนำทาง ถามจุดหมาย/สถานะหุ่น และบทสนทนาบริการพื้นฐาน จำกัดคำถามทั่วไปและการค้นเว็บ |
| ปิด | เพิ่มการสนทนาทั่วไปและค้นเว็บด้วยโมเดล Local และ SearXNG งานนำทางยังใช้การตรวจจุดหมายและสถานะหุ่นตามเดิม |

บันทึกทันทีเมื่อเปลี่ยนสวิตช์ มีผลกับข้อความถัดไป ทุกบทสนทนาใช้ค่าร่วมกัน ข้อความที่กำลังตอบอยู่จบตามโหมดที่เริ่มประมวลผล หน้า Robot Interface แสดงโหมดที่ใช้อยู่ด้านล่างและอัปเดตภายในประมาณ 5 วินาที ถ้าบันทึกไม่สำเร็จจะมีข้อความแจ้งและสวิตช์คงค่าเดิม

เฉพาะ Admin เปลี่ยนได้ ผู้ใช้อื่นอ่านค่าได้ ไม่ต้องเชื่อมหุ่นเพื่อเปลี่ยนโหมด การปิดข้อจำกัดไม่ได้เปิดบริการโมเดลหรือ SearXNG ให้เอง ต้องรันบริการเหล่านั้นเพื่อใช้แชตทั่วไปและการค้นเว็บ

ค่าบันทึกใน PostgreSQL `service_documents` ชนิด `ai-settings` รหัส `ai-scope-settings` และโหลดตอนเปิด Backend จึงคงอยู่หลังเปิดระบบใหม่ หากยังไม่เคยบันทึกจะใช้ `AI_NAVIGATION_ONLY` จาก environment เป็นค่าเริ่มต้น โหมด memory เก็บได้เพียงอายุ process ไม่มี migration ใหม่

API: `GET /api/ai/settings` สำหรับผู้ใช้ที่ล็อกอิน และ `PUT /api/ai/settings` สำหรับ Admin โดย body ต้องเป็น `{ "navigationOnly": true }` หรือ `false` เท่านั้น สถานะสาธารณะสำหรับอุปกรณ์อ่านค่าจาก `/api/kiosk/ai-status` และบันทึกการเปลี่ยนใน audit `ai.settings.update`

ผลตรวจ 23 ต.ค. 2569: Backend 81 tests, typecheck และ build ทั้งระบบผ่าน ตรวจสวิตช์ใน Chrome กับ Backend/PostgreSQL จริง ทดสอบตอบคำถาม/ค้นเว็บจริง และเปิด process ใหม่อ่านค่าที่บันทึกไว้ตรงกัน คืนค่าเป็นจำกัดนำทางหลังทดสอบ ไม่มีงานเดินเกิดขึ้น ผลนี้ยืนยันการสลับและเส้นทางบริการ ไม่ใช่การรับรองความแม่นยำคำตอบ
