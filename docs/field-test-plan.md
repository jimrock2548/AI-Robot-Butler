# แผนทดสอบหน้างานกับพี่ปลั๊ก

สถานะ: เตรียมแผนแล้ว ยังไม่ดำเนินการหรือถ่ายคลิปจริง

บันทึกวันที่ ผู้ทดสอบ ผู้ดูแลหุ่น รุ่น firmware รหัสแผนที่ IP และสภาพ Wi-Fi ก่อนเริ่ม
ใช้จุดหมายที่ตรวจพิกัดแล้ว มีผู้ดูแลหุ่นอยู่ด้วย และเว้นพื้นที่ทดสอบให้เหมาะสม

| ลำดับ | ทดสอบ | เกณฑ์ผ่าน | หลักฐานที่ถ่าย |
|---|---|---|---|
| 1 | เปิดระบบและอ่านสถานะ | แผนที่ตรงกับพื้นที่จริง ตำแหน่งถูกต้อง และ link ok | หน้าจอเว็บพร้อมภาพหุ่นในพื้นที่ |
| 2 | เพิ่ม/แก้ POI | อ่านกลับตรงกับข้อมูลที่ตั้ง ลิงก์ไม่ขาด และไม่เคลื่อนที่ | ก่อนบันทึก หลังบันทึก และ API log |
| 3 | พิมพ์ขอไป POI | เลือกจุดถูกและถึงปลายทางในระยะคลาดเคลื่อนที่ตกลงกับผู้ดูแล | บันทึกตั้งแต่ส่งข้อความจนถึงจุดหมาย |
| 4 | ยกเลิกงาน/หยุด | หุ่นหยุดตามเกณฑ์ผู้ดูแล และไม่มีคำสั่งล่าช้าตามมา | หน้าจอปุ่มหยุดและหุ่นพร้อมกัน |
| 5 | กลับแท่น | กลับแท่นและมีสถานะชาร์จจริง | เส้นทาง กลไกเข้าแท่น และค่า charging |
| 6 | หลายแผนที่ | สลับแผนที่ถูก POI ไม่ข้ามสถานที่ ระบุตำแหน่งใหม่ก่อนนำทาง | ชื่อแผนที่และตำแหน่งก่อน/หลัง |
| 7 | จุดประจำ | ไปถึงจุดยืนรอและหันถูก ไม่สับสนกับแท่น | POI จุดประจำและภาพปลายทาง |
| 8 | กดพูด/STT | ภาษาไทยและชื่อห้องตรง แก้ข้อความผิดก่อนส่งได้ | เสียงจริงและข้อความที่รู้จำ |
| 9 | Wake word | ไม่รับคำสั่งก่อนเรียกชื่อ หมดเวลาหลัง 8 วินาที และไม่รับเสียงตัวเอง | เสียงรบกวน/ไม่เรียกชื่อ/เรียกชื่อ |
| 10 | TTS | เสียงไทยฟังรู้เรื่อง ไม่ซ้อนกันและกดหยุดได้ | เสียงตอบพร้อมภาพปุ่ม |
| 11 | Admin รับช่วง | เห็นแชตสด AI ที่รอถูกยกเลิก เจ้าหน้าที่ส่งข้อความถึงหุ่นได้ | บันทึกสองหน้าจอและเสียงหุ่น |
| 12 | กำกวม/นอกขอบเขต | “ไปที่นั่น” ขอชื่อใหม่ “เรียกแท็กซี่” แจ้งทำไม่ได้ ไม่สร้างงาน | บทสนทนาและรายการงาน |
| 13 | เครือข่ายขาด | แสดง stale/dead และไม่รับงานใหม่ กลับมาเชื่อมต่อได้ | เวลาเริ่มขาด ลิงก์กลับ และ log |

แต่ละรอบเก็บ: case ID, expected, actual, pass/fail, เวลาตอบ, เวลาถึงจุดหมาย, ปัญหา และชื่อไฟล์คลิป
อย่านำผลจาก Mock หรือเสียงจำลองมาอ้างว่าอุปกรณ์จริงผ่าน

ลำดับคลิปนำเสนอ: ภาพรวมระบบ → พิมพ์/พูดไปจุดหมาย → หุ่นถึงจุด → Admin รับช่วง → คำขอทำไม่ได้ → สรุปผล
