# ตรวจรายการที่ยังไม่เคยทดลอง — 21 ตุลาคม 2569

สถานะ: **ยังไม่ครบทุกกรณี** รอข้อมูลผู้ดูแลหน้างานและอุปกรณ์เสียงจริง ไม่สั่งหุ่นเคลื่อนที่ระหว่างรอ

## ผลที่เพิ่มในรอบนี้

1. เปิดโหมดสำรวจ/สร้างแผนที่บนหุ่นจริง อ่านกลับว่า `mappingEnabled=true` แล้วเปลี่ยนกลับโหมดปกติ อ่านกลับว่า `false` ผ่าน
2. สำรองก่อนตรวจ และคืนแผนที่กับ pose ที่อ่านไว้ก่อนตรวจผ่าน ไม่มีข้อผิดพลาดตอนคืนค่า ไม่มีงานเดิน ลิงก์ปกติ คุณภาพหลังตรวจ 78/100
3. คงความเร็วที่ผู้ใช้ตั้งไว้ **0.50 m/s / 0.60 rad/s** ไม่คืนไปค่าจากการทดสอบรอบก่อน
4. ใช้ SpeechSynthesis จริงใน Chrome ที่เปิด headless บน PC พบ **`synthesis-failed`** ไม่ถือว่าพูดสำเร็จ แม้มีรายชื่อเสียงไทยให้เลือก
5. ตรวจสิทธิ์ไมค์ได้ `prompt` และ `enumerateDevices()` ในเบราว์เซอร์ทดสอบได้รายการว่าง จึงยังไม่มีหลักฐานการรับเสียงจริง ไม่เปิดบันทึกไมค์และไม่ใช้ transcript จำลองแทนผลจริง
6. Windows พบอุปกรณ์ AMD/Realtek สถานะ OK และทดสอบสังเคราะห์ **ภาษาอังกฤษ** ด้วย Microsoft Zira Desktop เป็น WAV ได้ 161,630 bytes หลังรันนอก sandbox ผลนี้ยืนยันเฉพาะการสร้างไฟล์เสียง ไม่ยืนยันเสียงไทยหรือเสียงที่ลำโพงหุ่น
7. พยายามเปิด Chrome โหมดปกติแบบเบื้องหลังเพื่อเทียบผล แต่ debugging port 9231 ไม่เปิดรับการเชื่อมต่อ จึงยังสรุปไม่ได้ว่าเกิดจาก headless, audio session หรือบริการเสียงไทย

หลักฐาน: [ทดสอบโหมดและคืนค่า](mapping-mode.json), [ทดสอบเสียงก่อนแก้](browser-audio.json), [ทดสอบเสียงและข้อความแจ้งหลังแก้](browser-audio-9229.json), [ไฟล์เสียงอังกฤษจาก Windows](windows-voice.wav)

## แก้จากปัญหาที่พบ

แก้ Robot Interface ให้แสดงสาเหตุเมื่อ TTS ล้มเหลว แยกเหตุการณ์จบเสียงกับข้อผิดพลาด กัน callback ของเสียงเก่ามารบกวนเสียงใหม่ และใช้ภาษาของเสียงที่ผู้ใช้เลือก ตรวจด้วย error จริงแล้วข้อความ `พูดเสียงไม่ได้ (synthesis-failed)` แสดงบนหน้าเว็บ Kiosk typecheck และ production build ผ่าน

## กรณีที่ต้องมีข้อมูล/คนหน้างานก่อนดำเนินการ

| รายการ | สิ่งที่ต้องมี |
| --- | --- |
| นำทางจริง / กลับจุดประจำ / กลับแท่น | มีคนอยู่ใกล้หุ่นพร้อมปุ่ม E-Stop และระบุ POI/เส้นทางที่ตรวจแล้วว่าโล่งในแล็บแคบ |
| ยกเลิก/หยุด/เครือข่ายหลุดขณะเดิน | ผู้ดูแลอยู่กับหุ่นและกำหนดพื้นที่ทดลองก่อนสร้างสถานการณ์ขัดข้อง |
| เดินสำรวจสร้างแผนที่จริง | พื้นที่และเส้นทางที่ผู้ดูแลยืนยัน ทดสอบเปิด–ปิด mapping ขณะอยู่กับที่แล้ว แต่ยังไม่ได้เดินสำรวจ |
| สลับแผนที่ต่างสถานที่ | มีไฟล์ของสถานที่ที่สองและตำแหน่งหุ่นจริงที่สอดคล้องกัน ไฟล์ในคลังที่ตรวจพบเป็นแผนที่ห้องแลป/สำเนา/ไฟล์สำรอง ไม่อ้างว่าเป็นอีกสถานที่ |
| รับเสียง / wake word / อ่านคำตอบและข้อความ Admin | เปิด Robot Interface บนอุปกรณ์ไมค์/ลำโพงที่จะใช้จริง มีคนพูดประโยคและฟังผล อนุญาตไมค์ในเบราว์เซอร์ แล้วเก็บผลถอดเสียงและ false activation |
| คงแผนที่/POI หลังรีสตาร์ตอุปกรณ์ | ผู้ดูแลพร้อมตรวจสภาพหุ่นและการระบุตำแหน่งใหม่ ไม่รีสตาร์ตอุปกรณ์แบบไม่มีคนอยู่หน้างาน |

ขอข้อมูลหน้างานผ่านคำถามในแชตแล้ว ยังไม่ได้รับคำตอบในช่วงตรวจนี้ ไม่ใช้การอ่านสถานะว่า `idle` หรือกริดแผนที่แทนการยืนยันว่าไม่มีคน/สิ่งกีดขวางรอบหุ่น ไม่เปลี่ยนค่าคุณภาพขั้นต่ำเพื่อให้ทดสอบเดินผ่าน Jetson ยังเว้นตามขอบเขตเดิม
