# ผลพัฒนาระบบควบคุมหุ่นจริง — 21 ตุลาคม 2569

ดำเนินงานต่อบน PC กับ Hermes จริงตามคำขอ โดยเว้น Jetson และ Field Test ไม่ส่งคำสั่งเดิน นำทาง กลับแท่น หรือหยุดฉุกเฉินในการตรวจรอบนี้

## ฟังก์ชันที่เพิ่มและแก้ไข

| ส่วน | ผลงานและตำแหน่งใช้งาน |
| --- | --- |
| ปรับความเร็ว | หน้า `/control` มี slider ความเร็วเดิน 0.05–0.50 m/s และหมุน 0.10–1.00 rad/s พร้อมปุ่มเลือกค่าเร็ว อ่านค่าจริงจากหุ่นแยกจากค่าที่กำลังแก้ กดบันทึกจึงเขียนค่าและอ่านกลับยืนยัน |
| โหมดหุ่น | ตัวเลือกโหมดปกติ/สำรวจเปลี่ยน `mapping/:enable` บนหุ่นจริง สำรองแผนที่ก่อนเปิดสร้างแผนที่ การเปลี่ยนโหมดไม่สั่งเดินสำรวจเอง |
| หลายแผนที่จริง | หน้า `/map-library` เพิ่มบันทึกจากหุ่น อัปโหลด ดาวน์โหลด และเลือกโหลดไฟล์ STCM หลายไฟล์ เก็บใน PostgreSQL พร้อมขนาดและ SHA-256 แยกจากแผนผัง JSON เดิม |
| ป้องกันโหลดแผนที่ผิดสถานะ | ต้องหุ่นว่าง ปล่อย lock และปิด mapping ก่อนโหลด สำรองของเดิมก่อนเขียน ตั้ง interlock ก่อนโหลดและเก็บลงฐานข้อมูลเพื่อกันนำทางหากโปรเซสถูกรีสตาร์ตกลางทาง |
| ระบุตำแหน่ง | หน้า `/map` → ระบุตำแหน่งหุ่น เลือกตำแหน่งที่หุ่นยืนจริงและกรอกทิศ ระบบอ่าน pose กลับยืนยันก่อนปลด interlock คุณภาพอย่างน้อย 50 ยังเป็นเงื่อนไขแยกก่อนนำทาง |
| กำแพงเสมือน | แสดงกำแพงจริงบนแผนที่ทุกหน้าที่ใช้ LiveRobotMap หน้า `/map` → กำแพงเสมือน เลือกสองจุดเพื่อสร้าง เลือกรายการเพื่อแก้ไข และลบเฉพาะกำแพงที่เลือกได้ มีการอ่านกลับยืนยัน |
| จุดประจำ | หน้า `/control` เลือกจาก POI ปัจจุบันของหุ่น บันทึกแยกจากค่าตัวอย่างในแผนผัง JSON สั่งกลับด้วยมือหรือเปิดหลังจบงานได้ ต้องเปิดนโยบายเองจึงเกิดงานกลับอัตโนมัติ |
| เงื่อนไขกลับจุดประจำ | กลับเมื่อได้รับผลสำเร็จจากงานผู้ใช้เท่านั้น ไม่วนกลับซ้ำจากงานระบบ ไม่กลับเพราะยกเลิก/ล้มเหลว/หยุดฉุกเฉิน ไม่คืนงานที่ค้างจากก่อนเปิดโปรแกรม หากลิงก์ คุณภาพ หรือ lock ไม่พร้อม ให้ข้ามและบันทึกเหตุผล ไม่รอสั่งเดินภายหลัง |
| ป้องกันข้อมูลข้ามสถานที่ | จุดประจำผูกกับลายนิ้วมือกริดแผนที่และอ่าน POI ใหม่ก่อนส่งงาน หากแผนที่เปลี่ยนต้องตั้งจุดประจำใหม่ |
| เสียง | เพิ่มรายการเสียงและอัตราการพูด ปุ่มทดสอบลำโพง และสถานะ HTTPS/localhost สำหรับเปิดไมค์ ใช้ STT/TTS และ wake gate ผ่านเบราว์เซอร์เดิม มีข้อความให้ตรวจคำที่ได้ก่อนส่ง |
| แชต Admin | ยืนยันบน Backend/ฐานข้อมูลจริงแล้วว่าแชตสด การรับช่วง ตอบถึง Robot Interface และคืนให้ AI ทำงาน |
| แก้ POI / ลิงก์ขาด | แยกผลบันทึก POI ที่อ่านกลับสำเร็จออกจากการ refresh แผนที่ภายหลัง ไม่ทำให้การบันทึกที่สำเร็จถูกแสดงเป็นล้มเหลวเพราะ refresh และใช้ gate ร่วมกันระหว่างแก้ POI ตั้งค่าหุ่น และเริ่มงาน |

ช่วงความเร็วข้างต้นเป็นเพดานที่ซอฟต์แวร์โครงการยอมให้ตั้ง ไม่ใช่ผลรับรองการเดินเร็วในพื้นที่จริง ความเร็วจริงยังขึ้นกับหุ่นและสิ่งกีดขวาง หลังตรวจคืนเป็น **0.10 m/s และ 0.30 rad/s** ผู้ใช้ปรับและกดบันทึกได้ที่หน้าควบคุม

## ปัญหาที่พบระหว่างทดสอบและแก้แล้ว

firmware รับ `PUT parameter` ด้วย `true` แต่ `GET` ถัดไปยังอาจให้ค่าเดิมทันที พบจริงเมื่อเขียน 0.15 แล้วอ่านได้ 0.10 ทำให้การตรวจครั้งแรกปฏิเสธการบันทึก

แก้โดยรออ่านซ้ำทุก 150 ms ภายใน 4 วินาที ตรวจค่าตรงก่อนสำเร็จ หากปรับความเร็วล้มเหลวให้คืนสองค่าก่อนหน้าและยืนยันการคืนด้วย ใช้การรออ่านกลับกับโหมด POI กำแพง และ pose ด้วย เพิ่ม regression test สำหรับพฤติกรรมนี้โดยเฉพาะ

การแก้ค่าหุ่นต้องไม่มีงาน/lock บน Backend และไม่มี action ที่ยังทำงานจาก RoboStudio หรืออุปกรณ์อื่น มี gate กันการเริ่มนำทาง/ขอ manual lock ระหว่างรอคำตอบการตั้งค่า

## วิธีใช้งาน

1. เปิด [หน้าควบคุม](http://localhost:3000/control) เพื่อเปลี่ยนโหมด ปรับความเร็ว และตั้งจุดประจำ ปล่อย lock และสิ้นสุดงานก่อนตั้งค่า
2. เปิด [หน้าแผนที่](http://localhost:3000/map) เลือกแท็บ POI / กำแพงเสมือน / ระบุตำแหน่งหุ่น
3. เปิด [คลังแผนที่](http://localhost:3000/map-library) ตั้งชื่อแล้วบันทึกแผนที่ปัจจุบัน หรืออัปโหลด `.stcm` ขนาดไม่เกิน 20 MB
4. เมื่อต้องการสลับสถานที่ กดโหลดบนหุ่น จากนั้นระบุตำแหน่งและทิศที่ตรงกับหุ่นจริงบนแผนที่ใหม่ ตรวจคุณภาพอย่างน้อย 50 ก่อนนำทาง และตั้งจุดประจำใหม่สำหรับแผนที่นั้น
5. เปิด [Robot Interface](http://localhost:3001/ai) → ตั้งค่าและตรวจสอบเสียง เลือกเสียงไทย/อัตราพูด ทดสอบลำโพง และใช้กดพูดหรือฟังคำเรียกเพื่อดูข้อความก่อนส่ง

ไฟล์ STCM ในคลังเก็บถาวรในฐานข้อมูล การโหลด STCM ผ่าน API หุ่นเป็นแผนที่ใช้งานปัจจุบัน ซึ่ง API ทางการระบุว่าไม่คงอยู่หลังรีสตาร์ตหุ่น จึงอาจต้องโหลดไฟล์ที่บันทึกไว้อีกครั้ง ไม่เรียก API บันทึกทับระบบหลายชั้นโดยอัตโนมัติ ดู [SLAMTEC API: maps/stcm และ system/parameter](https://docs.slamtec.com/opt/swagger-conf.json)

## ขอบเขตที่ยังไม่อ้างว่าทดสอบผ่าน

- การเดินจริง การกลับจุดประจำจริง การกลับแท่น หยุดฉุกเฉินและเครือข่ายขาดขณะเดิน: เว้นตามคำขอไม่ทำ Field Test
- การเปิดสำรวจและเดินสร้างแผนที่: ทดสอบสัญญา API และการอ่านกลับใน unit tests ส่วนรอบฮาร์ดแวร์ใช้การยืนยันโหมดปกติ ไม่ขับสำรวจพื้นที่
- อัปโหลดแผนที่ต่างสถานที่: ระบบรองรับ แต่รอบฮาร์ดแวร์โหลดสำเนาแผนที่เดิมกลับ ไม่อ้างว่าทดสอบตำแหน่งในอาคารอื่นแล้ว
- ไมค์และเสียงที่ได้ยินจากลำโพงบนหุ่น: ยังต้องมีคนพูด/ฟังจริง เครื่อง PC นี้มี SpeechRecognition และเสียงไทย Microsoft Pattara แต่การพบ API/รายการเสียงไม่ใช่หลักฐานความแม่นยำหรือคุณภาพเสียงจริง
- wake word ยังตรวจจาก transcript ของ browser STT ไม่ใช่ตัวตรวจคำปลุกแบบ local ที่ฟังตลอดเวลา การรับเสียงอาจใช้อินเทอร์เน็ตตามเบราว์เซอร์
- แชต Admin ส่งข้อความและ TTS ได้ ไม่ใช่การโทรเสียงสดสองทาง
- Jetson และการเก็บคลิป/ผล Field Test ไม่ดำเนินการในรอบนี้

## ตรวจซ้ำ

```powershell
pnpm --filter @hermes/backend test
pnpm typecheck
node scripts/check-live-controls.mjs
```

คำสั่งสุดท้ายแบบไม่ใส่ option อ่านสถานะอย่างเดียว หากใส่ `--apply` จะทดสอบเขียนค่าที่คืนกลับได้ รวมโหลดแผนที่เดิมและคืน pose ต้องไม่มีงานจากเว็บหรือ RoboStudio และหุ่นต้องอยู่กับที่ ไม่ควรรันระหว่างเจ้าหน้าที่แก้แผนที่/POI อยู่

ตรวจหน้าเว็บต้องเปิด Chrome debugging พอร์ต 9229 ก่อน แล้วรัน `node scripts/check-live-controls-browser.mjs` สคริปต์สร้างแชตทดสอบในฐานข้อมูลจริง และไม่กดปุ่มนำทาง
