# ตรวจความสามารถ AI หลังเปลี่ยนหน้าจอ — 23 ตุลาคม 2569

## ผลที่ผู้ใช้จะพบในระบบปัจจุบัน

หน้าใบหน้าใหม่เชื่อมต่อ API จริงและสนทนาทักทายได้ ทดสอบส่ง “สวัสดี” จาก Chrome ผ่าน ไม่มี API stub ในรอบนี้ ไม่มีงานหุ่นเกิดขึ้น

ค่าปัจจุบันยังเป็น `AI_NAVIGATION_ONLY=true` ตามขอบเขตบริการนำทางเดิม โมเดล Local และ SearXNG พร้อมทั้งคู่ แต่คำขอทั่วไป เช่น อวยพรวันเกิด และข่าวล่าสุด ถูกตอบให้ระบุจุดหมายแทน จึงยังไม่ถือว่าเว็บปัจจุบันเปิดใช้ทั้งสามความสามารถตามที่ถามพร้อมกัน การเปลี่ยนหน้าตาไม่ได้ลบเส้นทางแชต/ค้นเว็บออก และรอบตรวจนี้ไม่ได้เปลี่ยนโหมดหลักเป็นสนทนาทั่วไป

หุ่น 192.168.1.63:1448 ไม่ตอบในช่วงตรวจ (`linkStatus=dead`) นำทางจริงจึงยังยืนยันซ้ำไม่ได้ คำสั่งหยุดแบบ dryRun ผ่านบน Backend จริง ส่วนคำขอนำทางแบบ dryRun แจ้งแผนที่ไม่พร้อม ไม่มีคำสั่งเคลื่อนที่ส่งออก

## ผลตรวจเครื่องมือจริงแยกจากโหมดหลัก

ใช้ `apps/backend/scripts/check-ai-capabilities.ts` เรียก service จริงใน process แยกที่เปิดสนทนาทั่วไปชั่วคราว ใช้ Qwen Local จริงและ SearXNG จริง ไม่เปลี่ยนค่าของ Backend หลัก:

- เขียนคำอวยพร: ได้ข้อความตอบจากโมเดลจริง
- ค้นข่าว: ได้คำตอบและแหล่งอ้างอิง 4 รายการจากผลค้นหาจริง
- คำสั่งนำทางสองรูปประโยค กลับแท่น หยุด และคำขอกำกวม: ผ่าน dryRun 5 กรณี ใช้แผนที่/POI fixture เท่านั้น ไม่อ้างว่าได้อ่าน POI หรือสั่งหุ่นจริงในรอบนี้
- ผ่านสัญญาการทำงาน 10/10 กรณี รวมกรณีที่คาดให้โหมดนำทางปฏิเสธคำถามนอกขอบเขต ตัวเลขนี้ **ไม่ใช่คะแนนความถูกต้องของคำตอบหรือการนำทางจริง**

ยังพบปัญหาคุณภาพคำตอบ: คำอวยพรมีข้อความอ้างข้อจำกัด AI เกินจำเป็น และคำตอบข่าวตีความบาง snippet เกินหลักฐาน/สับสนเวลา จึงยืนยันได้ว่าค้นหาและสร้างข้อความทำงาน แต่ยังรับรองความแม่นยำข้อเท็จจริงไม่ได้

## จุดที่แก้ระหว่างตรวจ

1. แชตทั่วไป/ค้นเว็บในโหมดสนทนาเดิมอ่านแผนที่หุ่นแม้ไม่ต้องใช้ ทำให้หุ่นออฟไลน์แล้วคำตอบล้มเหลว แก้ให้โหลดข้อมูลจุดหมายเฉพาะเส้นทางข้อมูลอาคาร
2. คำสั่งนำทางเมื่ออ่านแผนที่ไม่ได้เดิมคืน HTTP 500 ทั่วไป แก้ให้คืน HTTP 503 `robot_map_unavailable` พร้อมข้อความตรวจการเชื่อมต่อ

เพิ่ม regression tests และตรวจ Backend 80/80, typecheck และ build ผ่าน ไม่มีการทดสอบเสียงจริงหรือการเดินจริง และไม่กลับไปทำรายการฮาร์ดแวร์อื่นที่พักไว้
