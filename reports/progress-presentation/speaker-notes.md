# โน้ตนำเสนอความคืบหน้า — 13 ตุลาคม 2569

14 สไลด์ ประมาณ 8–12 นาที; เติมชื่อผู้จัดทำและอาจารย์ในหน้าแรก

## 1. รายงานความคืบหน้าโครงงาน

แนะนำชื่อโครงงานและผู้จัดทำ รายงานครั้งนี้สรุปสถานะ ณ 13 ตุลาคม 2569 โดยใช้หลักฐานทดสอบเดิม เน้นความคืบหน้าซอฟต์แวร์ AI local และ Mock Test ที่เพิ่มล่าสุด ตอนนี้ยังไม่มีผลตรวจรับการเคลื่อนที่จริงจากผู้ช่วย เป้าหมายของการนำเสนอคือแยกสิ่งที่ทำแล้วออกจากสิ่งที่ต้องตรวจต่อ ไม่ประเมินเปอร์เซ็นต์รวมโดยไม่มีเกณฑ์ถ่วงน้ำหนัก



## 2. ภาพรวม: ซอฟต์แวร์ทำแล้ว แต่ยังรอตรวจรับหน้างาน

ระบบเว็บและฐานข้อมูลมีโค้ดและหลักฐานทดสอบแล้ว AI วิธีหนึ่งและสองพร้อม benchmark ใช้บน PC ได้ ส่วนงานควบคุมหุ่นมีเส้นทางรองรับแต่ต้องตรวจพฤติกรรมจริง การเลือกโหมดสำรวจยังเป็น preference ฝั่งเว็บ Jetson ระบบเสียง และบริบทถามกลับยังไม่พร้อมใช้งาน เราจึงไม่สรุปว่าโครงการเสร็จสำหรับหน้างานทั้งหมด

หลักฐาน: PROGRESS.md; docs/mock-robot.md

## 3. สิ่งที่เพิ่มในรอบล่าสุด

วันที่ 7 ตุลาคมขยายภาษา AI และเก็บผล benchmark วันที่ 11 เพิ่มตัวเลือกโหมดปกติ/สำรวจแบบออฟไลน์ วันที่ 12 จัดรูปเล่ม สไลด์ และเพิ่ม Mock Test แบบเชื่อมต่อหุ่น ผลทดสอบ backend หลังเพิ่ม mock ผ่าน 52 รายการ รายงานวันนี้จัดทำสไลด์ความคืบหน้า ไม่ได้ทดลองหุ่นหรือโมเดลใหม่

หลักฐาน: PROGRESS.md; reports/ai-benchmark/hybrid.json; reports/presentation/validation.json

## 4. โครงสร้างระบบที่พัฒนาแล้ว

Admin และ Kiosk เรียก Backend กลาง Backend ตรวจสิทธิ์และงานก่อนเลือก adapter ของหุ่น ตอนนี้มีสามทาง: RobotSim เดิม หุ่น Hermes จริง และ MockHermesClient ที่เลียนแบบการเชื่อมต่อ โดย mock บังคับใช้ memory และไม่เรียก API ฮาร์ดแวร์จริง โมเดล local ยังเป็น Qwen จริงบนพีซีหากเปิดบริการ

หลักฐาน: config.ts; driver.ts; mockHermesClient.ts; chatService.ts

## 5. เว็บ แผนที่ และการจัดการจุดหมาย

เว็บผู้ดูแลและผู้ช่วยแยกกัน มีบทบาทผู้ใช้และ token ของ Kiosk ด้านแผนที่แสดงกริด หุ่น แท่น LiDAR และ POI ได้ รวมซูมและลาก ส่วน POI เพิ่ม แก้ ลบ และชื่อเรียกอื่นได้ มีการอ่านกลับยืนยัน แต่การตรวจ CRUD ทุกกรณีบนหุ่นจริงยังไม่ครบ หลักฐานอ่านข้อมูลจริงเป็นของรอบก่อน ไม่ใช่การเชื่อมต่อในขณะนำเสนอ

หลักฐาน: LiveRobotMap.tsx; RobotMapEditor.tsx; PROGRESS.md

## 6. Mock Test: ดูหน้าตาแบบต่อหุ่นโดยไม่มีอุปกรณ์

Mock Test เป็นความคืบหน้าใหม่ที่ช่วยพัฒนาต่อเมื่อไม่อยู่ใกล้หุ่น มี telemetry สด แผนที่กริด LiDAR 360 จุด home และ POI 4 จุด ใช้ UI เส้นทางแผนที่สดเดียวกับตอนต่อ Hermes ทุกหน้ามีป้ายข้อมูลจำลองที่เกี่ยวข้อง รองรับงานนำทางและควบคุมจำลอง ไม่จำลอง SLAM หรือการหลบสิ่งกีดขวางอย่างครบถ้วน

หลักฐาน: mockHermesClient.ts; mockConnected.test.ts; docs/mock-robot.md

## 7. AI: วิธีที่ 1–2 ทำแล้ว วิธีที่ 3 ยังค้าง

วิธีที่หนึ่งขยายกฎประโยคและชื่อเรียกอื่น วิธีที่สองใช้โมเดลตีความประโยคอ้อมเป็น JSON โดยเลือกรหัสจากรายการจริง ทั้งสองทำแล้วบน PC ส่วนวิธีที่สามคือจำคำถามที่ค้าง เช่น ห้อง A หรือ B แล้วนำคำตอบห้อง A ไปเชื่อมกับคำขอเดิม ตอนนี้มีข้อความถามกลับ แต่ยังไม่มีสถานะบทสนทนาเพื่อสร้างงานจากคำตอบต่อเนื่อง

หลักฐาน: robotLanguage.ts; robotIntent.ts; robotAiService.ts; PROGRESS.md

## 8. ผล benchmark AI ที่บันทึกไว้

ชุด regression 40 กรณีที่ใช้พัฒนาผ่านเพิ่มจาก 21 เป็น 40 สำหรับ hybrid และ model เป็นหลัก ตัวชี้วัดเสนอเดินผิดเจตนา/จุดหมายลดจาก 4 เป็น 0 ในชุดนี้ ผลทั้งหมดบันทึกวันที่ 7 ตุลาคม ใช้ dry-run บน PC ไม่มีการเดินจริง และยังไม่ใช่ unseen evaluation หรือการรับประกันทุกประโยค

หลักฐาน: reports/ai-benchmark/{baseline,hybrid,model}.json — 7 October 2026

## 9. ผลตรวจล่าสุดหลังเพิ่ม Mock Test

หลังเพิ่ม Mock Test มี backend tests ผ่าน 52 รายการและ typecheck สามแอปผ่าน รวมการตรวจที่บังคับ memory แม้ตั้ง DB_MODE เป็น pg และดัก fetch เพื่อยืนยันว่าไม่เรียกเครือข่ายหุ่น smoke test ของระบบที่เปิดอยู่ตรวจแผนที่ Kiosk AI dry-run และเคลื่อนที่จำลองแล้ว ข้อมูลนี้เป็นผลเดิมล่าสุด ไม่ได้รันใหม่ขณะทำสไลด์วันนี้

หลักฐาน: PROGRESS.md; mockConnected.test.ts; check-robot-mock.mjs

## 10. โหมดปกติ / สำรวจ: ฝั่งเว็บทำแล้ว

ผู้ควบคุมเลือกโหมดปกติหรือสำรวจได้แม้ออฟไลน์และจำตัวเลือกในเบราว์เซอร์ แต่การกดเลือกไม่ได้เปลี่ยน mappingEnabled ของหุ่น งานที่ยังค้างคือเชื่อม requested mode กับสถานะที่อุปกรณ์อ่านกลับยืนยัน ไม่เริ่มเดินหรือสำรวจอัตโนมัติเมื่อเชื่อมต่อใหม่ ในห้องแลปควรเริ่มตรวจแบบผู้ใช้บังคับเดินสร้างแผนที่ก่อนอัตโนมัติ

หลักฐาน: RobotOperatingMode.tsx; PROGRESS.md

## 12. งานที่ยังค้าง เรียงตามลำดับเสนอทำต่อ

แผนนี้เป็นลำดับที่เสนอ ไม่ใช่กำหนดวันหรือการอนุมัติให้เริ่มงานใหม่ หนึ่งเพิ่มบริบทถามกลับและ benchmark หลายข้อความ สองเชื่อมโหมดจริงและอ่านกลับยืนยัน สามตรวจรับการเดินและพฤติกรรมเครือข่ายในพื้นที่ที่ผู้ใช้ควบคุม สี่กลับไปทำ build และวัดโมเดล/เสียงบน Jetson ซึ่งพักตามคำขอ ยังไม่มีผล benchmark Jetson

หลักฐาน: PROGRESS.md; SPEC.md; docs/jetson-ai.md

## 13. แนวทางเดโมวันนี้: ใช้ Mock Test

หากจะสาธิตใช้ Mock Test และตรวจป้ายก่อน แสดงหน้า Control ที่มีแผนที่ LiDAR และ POI แล้วเปิด Kiosk สั่งไป POI จำลองดูตำแหน่งและงานเปลี่ยน ทดลองหยุดหรือกลับแท่นเฉพาะตัวจำลอง เส้นทางเดโมในสไลด์เป็นขั้นตอนแนะนำ ไม่มีการเปิดบริการใหม่หรือส่งคำสั่งใดระหว่างสร้างสไลด์ การจำลองไม่ใช่การหลบสิ่งกีดขวางหรือ SLAM จริง

หลักฐาน: docs/mock-robot.md; scripts/start-robot-mock.ps1

## 14. พร้อมทดสอบซอฟต์แวร์ต่อ แม้ยังไม่มีหุ่น

สรุปว่าซอฟต์แวร์เว็บ AI local และ Mock Test มีหลักฐานตรวจแล้ว ทำให้พัฒนาต่อได้ตอนอุปกรณ์ไม่พร้อม ความเสี่ยงที่ยังต้องคลี่คลายคือการเดินจริง โหมดสำรวจจริงและการรันบน Jetson ถามกรรมการว่าควรให้ความสำคัญกับบริบทสนทนาหรือการตรวจรับอุปกรณ์ในรอบถัดไป และแจ้งว่าเปอร์เซ็นต์ benchmark ไม่ใช่เปอร์เซ็นต์โครงการเสร็จ
