# ผลแก้ไข AI และตรวจระบบหุ่นจริง — 21 ตุลาคม 2569

แก้ปัญหาคำถามหลายชนิดตกไปเป็นคำทักทายซ้ำ และผลโมเดลที่เสนอการนำทางทั้งที่ไม่มีจุดหมายชัดเจน ตรวจบน Backend จริง `http://localhost:4000` ผ่าน Robot Interface `http://localhost:3001/ai` กับ Hermes `192.168.1.63:1448` ไม่ใช้ Mock backend ในการตรวจ integration รอบนี้

## สิ่งที่แก้

- แยกคำทักทาย ขอบคุณ กล่าวลา ความสามารถ และการขอเจ้าหน้าที่ออกจากกัน
- อ่านรายชื่อจุดหมายและพิกัดจาก POI ปัจจุบันบนหุ่นโดยตรง กรองจุดที่ไม่เปิดให้ผู้ใช้เลือก และแจ้งเมื่ออ่านข้อมูลไม่ได้
- ตอบแบตเตอรี่/สถานะจาก telemetry ที่เชื่อมต่อปกติ ไม่ยืนยันค่าปัจจุบันเมื่อข้อมูลขาดหรือล่าช้า
- คำถามชั้นและเวลาเปิดปิดแจ้งว่าไม่มีข้อมูลยืนยัน ไม่สร้างรายละเอียดขึ้นเอง
- ตรวจผล LLM เพิ่ม: การนำทาง/ถามตำแหน่งต้องตรงกับจุดหมายที่ระบุชัดเจนเพียงจุดเดียวในข้อความ หากไม่มีหรือกำกวมให้ถามกลับ แม้โมเดลให้ confidence สูง
- คำสั่งที่กฎเข้าใจชัดเจนทำงานได้โดยไม่ต้องเปิดโมเดล ส่วนข้อความที่ต้องใช้โมเดลแจ้งข้อจำกัดเมื่อโมเดลไม่พร้อม
- แสดงความพร้อมของกฎและโมเดลแยกกัน ลดความสับสนจากสถานะ textReady
- คงการตรวจ lock, คุณภาพระบุตำแหน่ง และเงื่อนไขความปลอดภัยก่อนส่งคำสั่งจริง

## สถานะหุ่นและขอบเขตผล

รอบตรวจได้ `simulated=false`, `linkStatus=ok`, POI 8 จุด, `mappingEnabled=false`, ไม่มีงานหุ่นก่อนและหลังตรวจ คุณภาพระบุตำแหน่งอยู่ที่ **35/100** ต่ำกว่าเกณฑ์นำทาง **50**

ไม่ได้ส่งคำสั่งเดิน กลับแท่น หยุดงาน หรือแก้แผนที่/POI บนหุ่น ผล dry-run ยืนยันการตีความคำสั่งและการเลือกจุดหมาย ไม่ได้ยืนยันว่าหุ่นสามารถวางเส้นทางหรือเดินถึงจุดหมายได้ ต้องตรวจคุณภาพระบุตำแหน่งและพื้นที่ก่อนทดลองเดินจริง

โมเดลยังรันบนคอมพิวเตอร์ Local รอบบังคับโมเดลใช้ประมาณ 4.3–5.4 วินาทีต่อคำสั่ง และคำสั่งอ้อมผ่านระบบเว็บรอบหนึ่งใช้ประมาณ 9.7 วินาที ตัวเลขเป็นผลตัวอย่าง ไม่ใช่ benchmark latency ขนาดใหญ่

## การเปิดระบบหุ่นจริง

`scripts/start-robot-control.ps1` ใช้ `AI_MODE=local` เป็นค่าเริ่มต้นแล้ว โดยต้องเปิดบริการโมเดลแยกตามเดิม ตัวเลือก `-LocalAI` เดิมยังรับได้ หากต้องการเปิดเฉพาะกฎพื้นฐานโดยปิดโมเดลให้ใช้ `-WithoutAI`

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-robot-control.ps1 -Service backend
powershell -ExecutionPolicy Bypass -File scripts/start-robot-control.ps1 -Service admin
powershell -ExecutionPolicy Bypass -File scripts/start-robot-control.ps1 -Service kiosk
```

รันแต่ละบริการในคนละ terminal เปิด [Admin](http://localhost:3000) และ [Robot Interface](http://localhost:3001/ai) การเปิดบริการเริ่มอ่านสถานะหุ่น ส่วนคำสั่งเคลื่อนที่เกิดจากการสั่งงานของผู้ใช้ภายใต้การตรวจความปลอดภัยของ Backend
